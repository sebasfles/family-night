# Impostor: technical

Stack, conventions and verification commands are in [docs/TRD.md](../../TRD.md).
Types and payloads are in [the plan](../../implementation-plan.md#tipos-en-sharedsrcdomaints); this file does not repeat them.

## Structure

- `shared/src/impostor/rules.ts`: the pure rules (role assignment, vote resolution, win evaluation, impostor limits by player count); no I/O, no AWS, randomness comes from the caller so tests can seed it.
- `shared/src/domain.ts` and `shared/src/api.ts`: the Impostor config, public state, secret and request types, shared with `platform`.
- `shared/src/schemas.ts`, exported as `@family-night/shared/schemas`: the config's zod schema, imported only by the api so zod stays out of the web bundle.
- `api/src/services/impostor/`: match preparation, vote handling, round close, next round, guess, skip guess and the elimination triggered by a member leaving or being kicked.
- `api/src/data/impostor-words.json`: the word bank, generated by prompt; each word has an id (stored in `usedWordIds`), a category, the word and its clue.
- `web/src/games/impostor/`: lobby and config panels, card, turn order, voting list, reveal, last chance, final, match header; `myVote.ts` keeps the caller's own vote per match and round in `sessionStorage` so a reload keeps it marked.
- `web/src/routes/$code/impostor.tsx`: the screen; the `$code/route.tsx` effect of `platform` sends everyone here when the current match is Impostor.

## Endpoints owned

Every match route lives under its room: `{match}` below is `/api/rooms/{code}/matches/{matchId}`.

- `PUT {match}/votes`: cast or change the caller's vote for the round.
- `POST {match}/close-voting`: host closes the vote early.
- `POST {match}/next-round`: host leaves the result; goes on, opens the last chance or finishes, as `outcome()` says.
- `POST {match}/guess`: the caught impostor picks a word.
- `POST {match}/skip-guess`: host skips the guess.
- `GET /api/words/categories`: categories with their word counts, for any identified player.

Shared with `platform`, which owns the route and calls into this module by game type: start, rematch and `PUT /api/rooms/{code}/config` (config validation and preparation), `{match}/me` (the caller's secret), and `/leave` and `/kick` (elimination).
Routes, roles and errors are in [the plan](../../implementation-plan.md#impostor) and [error codes](../../implementation-plan.md#códigos-de-error).
Errors this module raises: `INVALID_CONFIG` (with a specific Spanish message for too many impostors or no category), `NOT_ENOUGH_PLAYERS`, `INVALID_VOTE`, `NOT_GUESSER`, `STALE_ROUND`, `CONFLICT`.
A guess outside the last-chance phase answers `STALE_ROUND`.
There is no generated API spec; the typed contract is `shared/src/api.ts`.

## Depends on

- `platform`: auth headers, room and member lookup, the version-based optimistic locking, the snapshot builder, the event publisher, the `Matches`, `Rooms` and `RoomMembers` repos, presence (who is online at start).
- `infra`: the `MatchSecrets` and `Votes` tables with TTL on `ttl`.

## Depended on by

- `platform`: the lobby embeds the config panel and the room snapshot carries the Impostor public state.

## Configuration

None of its own: no env vars or flags.
The word bank ships inside the API bundle.

## Testing

- `shared`: Vitest on the pure rules, with the minimum cases of [the plan](../../implementation-plan.md#testing).
- `api`: integration of the handlers against DynamoDB Local with the publisher mocked, including 20 concurrent votes closing the round exactly once, `STALE_ROUND`, and a test that serializes a live match's snapshot and finds neither word nor clue.
- `web`: Testing Library on the lobby panel, card, voting, reveal, last chance and final screens.
- Run serially with `--runInBand` or the Vitest equivalent; the exact commands are in `docs/TRD.md`.
