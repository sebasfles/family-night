# 0002 Identity and rooms

## Goal

A family opens the site, each phone gets its permanent name, one of them creates a room and shares the link by WhatsApp, the others join from it, and every phone shows in real time who is in, who is host and who is away; reloading or minimizing never loses the place.
This is the platform every game sits on.

## Scope

- shared: `domain.ts` (Player, RoomSnapshot, member), `api.ts` (every request and response of the endpoints below, error envelope and codes), `events.ts` (`room.updated`, `member.kicked`, `room.closed`), `constants.ts` (room code alphabet, 20 members, 24 h TTL, 20 s ping, 45 s online, 60 s host silence).
- api: auth by headers with constant-time hash check; `players` service with `names.json` (100 masculine animals, 100 masculine adjectives, generated by the om-developer) and the transactional unique name; `rooms` service (create with code retry, idempotent join and rejoin, leave, kick, host handover, lazy host transfer after 60 s of real silence, 20-member cap, TTL recalculation); `presence` (ping publishing only on return, away moving `lastSeenAt` back 60 s); snapshot builder with `version` and `serverTime`; `publish.ts` signed with SigV4, logged and never failing the request; repos for Players, PlayerNames, Rooms, RoomMembers; the events authorizer Lambda replacing 0001's deny-all: validates `playerId:playerToken`, allows `/rooms/{code}` only to members, TTL 300 s.
- Endpoints: `POST /players`, `GET /players/me`, `POST /rooms`, `GET /rooms/{code}`, `POST /rooms/{code}/{join,leave,ping,away,kick,host}` with the plan's status codes and Spanish messages.
- web: identity bootstrap in `__root.tsx` (create or validate, 401 starts over); home with greeting, Crear sala, code field with uppercase and Unirme; `$code/route.tsx` with code validation and redirect, join on load, room query, realtime subscription authenticated with `playerId:playerToken`, ping every 20 s while visible, away on hide with `fetch keepalive`, rejoin and resync on visible, reconnection with backoff and invalidate; `$code/index.tsx` lobby: code large, Copiar link (clipboard with fallback, toast), Compartir (share sheet, `wa.me` fallback, AbortError ignored), member list with crown, online or "ausente" recomputed every 5 s, score, "(tú)", host menu (Hacer host, Sacar de la sala), Salir with confirmation, "Esta sala no existe o ya expiró" with a create button, `member.kicked` sends the kicked phone home; game selector cards with Impostor, Just One and Wavelength all shown as "Próximamente" until 0003 (the match lifecycle arrives with the first game).
  Every request with a body sends `x-amz-content-sha256`.
- Tests: Vitest unit on name generation, room code, snapshot builder and online derivation; api integration against DynamoDB Local with the publisher mocked: name collision forced, create and join, idempotent rejoin, 21st member refused, host handover and lazy transfer, away then ping publishes once; web Testing Library on home and lobby states; a test that the snapshot carries no `tokenHash`.
- Screenshots of home and lobby (empty, with members online and away, as host and as member, room not found) at 390, 768 and 1280 px with mocked data, in the workspace, refreshed every round.
- Docs: `document-task` updates platform `trd.md`, `database.md` and `ard.md` where the implementation decided something.

## Out of scope

- Any Terraform change; the authorizer resource exists since 0001, only its code changes.
- Deferred: QR code of the room (optional in the plan).

## Acceptance

1. First visit shows "Hola, {Animal Adjetivo}" with a masculine name; reload and a new tab keep it; clearing localStorage gives a new one.
2. Crear sala opens `/{CODE}` with a 4-letter code from the alphabet without I, L, O; the creator is host.
3. Opening `/{CODE}` on another phone joins and both phones list both members within a second; `/abcd` normalizes to `/ABCD`; a bad code goes home; an unknown code shows the not-found message and its button.
4. The 21st member gets `ROOM_FULL` and the message.
5. Copiar link copies `https://family-night.fless.dev/{CODE}` and shows "¡Link copiado!"; Compartir opens the share sheet on a phone and `wa.me` on desktop; the link previews in WhatsApp with title and image.
6. Hiding the tab turns the member grey "ausente" on the other phones at once; showing it again turns it green and refreshes the room.
7. A host silent for 60 s loses the role to the oldest online member on the next request of anyone; the away call alone does not.
8. Kick sends the kicked phone to the home page; leave removes the member after confirmation; host handover moves the crown.
9. Reloading in the lobby returns to the same lobby with the same identity; killing the WebSocket makes the client reconnect and refetch.
10. Nobody can subscribe to a room's channel without a valid token or without being a member; the snapshot and events contain no token hash.
11. Every verification target passes; screenshots of every screen and state are in the workspace.

## Context & decisions

Consolidated 2026-10-17 by the om-reviewer with Sebastian through the om-manager.

Decisions (Sebastian):

- Host leaves: the crown goes at once to the oldest online member, else the oldest member.
- Last member leaves: the room stays until its TTL; the next to join becomes host.
- Kick is not a ban: opening the link again rejoins.
- Adjustment to the plan's "al volver: join": on visible the web pings; 403 `NOT_MEMBER` sends it home with "Te sacaron de la sala", otherwise it refetches and resubscribes. Only opening or reloading `/{CODE}` joins. Reason: a kicked ghost must not rejoin when its phone is unlocked.
- Adjustment to Acceptance 3, 5, 6, 9, 10: pre-merge evidence is tests, screenshots and the om-reviewer's handshake test (the live authorizer is 0001's deny-all until merge). The PR description carries a two-phone smoke checklist Sebastian runs on production after merge; a failure is a fix task.

Decisions (om-reviewer, accepted):

- `x-amz-content-sha256` on every POST, bodyless ones included (empty-body hash), computed in `web/src/api/client.ts`.
- api integration tests start DynamoDB Local in Docker from a vitest `globalSetup` (random port, tables keyed as `infra/stacks/app/database.tf`), fail loudly without Docker, never skip. Workflows unchanged.
- Authorizer: `EVENT_CONNECT` checks identity; `EVENT_SUBSCRIBE` checks identity and membership of the channel's room; anything else denied. Allow cached 300 s (AppSync keys on token, operation and channel), deny returns `ttlOverride: 0`. Logs `playerId`, operation, channel and decision, never the token.
- Debt: a kicked or departed member can resubscribe within the 300 s allow cache. `document-task` records it in platform `ard.md`.
- Items past `ttl` not yet deleted by DynamoDB are treated as absent on read.
- RoomMembers gets a real-activity timestamp besides `lastSeenAt`; host transfer uses it, so the away setback never counts. Transfer runs on any member's room request and goes to the oldest online member by `joinedAt`.
- Every published snapshot has a new `version`: joins of new members, away, and returns to online (ping or join after 45 s) bump it; plain pings do not.
- Response shapes per the plan's Salas table: leave `{ ok: true }`, ping `{ serverTime }`, away 204 with no body and header auth (`platform/ard.md`). Target not a member on kick or host: a new code with its Spanish message, added in `shared/src/api.ts`.
- Ping answers `{ room }` instead of the plan's `{ serverTime }` (the snapshot carries `serverTime`), so quiet members stay green without an extra GET every tick; asked by the om-developer before round 1. The client applies a snapshot when its `version` is greater, or equal with a newer `serverTime`.
- `currentMatch` is typed `null` in 0002; 0003 widens it. Score shows 0.
- Screenshots in `.workspaces/0002_identity_and_rooms/screenshots/`; the realtime client must not break when its env vars are absent.

Constraints: `platform/ard.md` (token hash in constant time, server-only publish, version rule, own WebSocket client, keepalive away), `platform/database.md` invariants, `docs/TRD.md` conventions; no token or `tokenHash` in snapshots, events or logs.

Decisions not recorded in the plan:

- Version bump is computed, not flagged: `changesSnapshot` compares host, membership, name, score and online status before and after at the same instant; any difference bumps and publishes, so plain pings and online rejoins never do.
- Bumping writes are one `TransactWriteItems` (room conditional on `version`, member puts and deletes); non-bumping writes are a conditional put of the caller's row plus a room `ttl` renewal. Four attempts with jitter, then `CONFLICT`.
- `lastActiveAt` on RoomMembers is the real-activity timestamp; `touch` sets it with `lastSeenAt`, away moves only `lastSeenAt`. Away does not run the host transfer; every other member request does.
- A host-only command evaluates the host after the lazy transfer; when it then fails (`NOT_HOST`, `TARGET_NOT_MEMBER`) the transfer is not written and the next ping does it.
- Kick of oneself is `VALIDATION_ERROR`; handing the crown to oneself is a no-op. `TARGET_NOT_MEMBER` is 409.
- An invalid room code in the path is 400 `VALIDATION_ERROR`; the web never sends one. Unknown routes answer 404 `NOT_FOUND` in the envelope; unhandled errors 500 `INTERNAL_ERROR`, logged.
- `POST /players` answers 200 (the plan marks 201 only for rooms). `GET /players/me` renews `Players.lastSeenAt`.
- Authorizer token is `playerId:playerToken`; subscribe accepts only the exact channel `/rooms/{CODE}` (no wildcard). A thrown error denies.
- Web cache holds `{ snapshot, clockOffsetMs }`; the offset is taken when a snapshot is applied. The join on `/{CODE}` is a query with `gcTime: 0`, so opening or reloading joins and nothing else does.
- Identity falls back to memory when localStorage throws, so a private tab still works for the session.
- `routeFileIgnorePattern: '\.test\.'` in the router plugin, so route tests next to routes are not treated as routes.
- Request log line per request (method, path, status, ms, playerId).
